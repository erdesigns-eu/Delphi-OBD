# Catalogs

Delphi-OBD keeps its tables — PIDs, DTCs, NRCs, DIDs, J1939 PGNs / SPNs /
FMIs, OEM diagnostic catalogues, VIN data, EV battery decode rules, drive
cycles, radio-code databases — as **JSON files** under `catalogs/` instead
of baking them into source. Adding an entry is a JSON edit; no recompile.

[`catalogs/SOURCES.md`](../catalogs/SOURCES.md) records where imported
open data came from and under which licence.

[`catalogs/INDEX.md`](../catalogs/INDEX.md) lists every OEM catalogue with
its entry counts. It is generated by `python3 tools/catalog_index.py --write`.
Each brand row separates brand-specific (*Own*) entries from entries
*Inherited* from a shared base, and counts entries marked `verified: true`.

## Where they live

```
catalogs/
├─ obd2/                    Standard OBD-II: Mode 01 PIDs, Mode 06 MIDs / TIDs,
│                           generic DTC text, UDS NRC text, WWH-OBD DIDs
├─ j1939/                   J1939 PGNs, SPNs and FMIs
├─ uds/                     Generic UDS DIDs and routines
├─ kwp/                     KWP2000 common identifiers
├─ oem/<vendor>/            Per-vendor overlays (dids / pids / dtcs) for TOBDOEMCatalog
├─ <vendor>.json            Full OEM diagnostic catalogues (ECUs, DIDs, routines,
│                           coding, adaptations, actuators, live data)
├─ dtc-<vendor>.json        Manufacturer DTC catalogues
├─ _shared/                 Shared OEM base catalogues that brand catalogues
│                           inherit through "extends" (generic template data)
├─ motorcycle/ agricultural/ marine/ powersports/
│                           OEM catalogues for the other vehicle classes
├─ vin/                     VIN regions, countries, WMIs, plants, VDS rules
├─ ev-battery/              EV battery decode rules per vendor (+ _manifest.json)
├─ radio-code/              Becker 4 / 5 and Ford V code databases
├─ range-profiles/          Editable normal bands for OBD Studio values
├─ adapter/                 Adapter capabilities and init sequences
├─ tacho/                   Digital tachograph data types
├─ obd2-pids.json, uds-standard.json, uds-nrc.json, j1939-pgns.json,
│  mode06-*.json, service-routines.json, drive-cycle-generic.json,
│  key-platforms-*.json, …  Shared top-level catalogues
└─ _schema/                 JSON Schema (draft 2020-12) for every catalogue type

data/schemas/               Schemas for host-supplied sidecar files
├─ flash-image-applicability.schema.json
├─ oem-coding-catalog.schema.json
└─ oem-flash-handshake-catalog.schema.json
```

The catalogue components look in `catalogs/` next to the executable by
default. Set `CatalogDir` on the components that publish it, or deploy
`catalogs/` with the application.

## Loaders

Different catalogue families have their own loaders:

| Loader | Reads |
|---|---|
| `TOBDCatalogStore.Default` (`ERD.Catalog`) | Strict v1 catalogues with a `type` field: `obd2-pid`, `obd2-dtc`, `uds-nrc`, `uds-did`, `j1939-pgn`, `j1939-spn`, `j1939-fmi`, `adapter-capabilities` |
| `TOBDServiceCatalog.Default` (`ERD.Service.Catalog`) | The richer `obd2-pids.json` and `dtc-*.json` shapes that `TOBDLiveData` and `TOBDDTCs` use for names, units, decoder formulas and DTC text |
| `TOBDOEMCatalog` component (`ERD.OEM.Catalog`) | `oem/<vendor>/*.json` overlays (DIDs, PIDs, DTCs, SPNs, FMIs, PGNs), registered with the OEM registry |
| OEM extensions (`ERD.OEM.Catalog.Loader`) | `<vendor>.json` full catalogues, merged over each extension's built-in entries; `SetCatalogSearchPath` overrides the search path |
| `TOBDVINCatalog`, `TOBDDriveCycleCatalogComp`, `TOBDEVBatteryCatalogComp` | `vin/`, drive-cycle and `ev-battery/` catalogues (OBD Catalogs palette page) |
| `TOBDCodingOptionCatalog.Default` (`ERD.Coding.OptionCatalog`) | Host-supplied coding-option catalogues (`data/schemas/oem-coding-catalog.schema.json`) |
| `TOBDFlashOEMCatalog` (`ERD.Flash.OEM.Catalog`) | Host-supplied flash-handshake overrides (`data/schemas/oem-flash-handshake-catalog.schema.json`) |
| `TOBDFlashImageApplicability` (`ERD.Flash.ImageApplicability`) | Firmware-image applicability sidecars (`data/schemas/flash-image-applicability.schema.json`) |

### The strict catalogue store

```pascal
TOBDCatalogStore.Default.LoadFile('catalogs/obd2/pids-mode01.json');
TOBDCatalogStore.Default.LoadDirectory('catalogs/obd2');

var Desc: TOBDPIDDescriptor;
if TOBDCatalogStore.Default.FindPID('01', $0C, Desc) then
  ShowMessage(Desc.Name + ' [' + Desc.UnitName + ']');

var Text: string;
if TOBDCatalogStore.Default.FindText(ckUDSNRC, $33, Text) then
  ShowMessage(Text);
```

`FindPID` returns the descriptor (ID, name, length, unit, decoder name,
scale, offset, min / max, description). `FindText` searches every loaded
catalogue of one kind (`ckOBD2DTC`, `ckUDSNRC`, `ckJ1939PGN`,
`ckJ1939SPN`, `ckJ1939FMI`, …). A missing file, malformed JSON, a missing
`type` or `entries` field or an unsupported `version` raises `EOBDConfig`
with the file name in the message; `LoadDirectory` stops at the first bad
file and keeps the catalogues already loaded.

## Formats

### PID / DID catalogues (`obd2-pid`, `uds-did`)

```json
{
  "$schema": "https://erdesigns.eu/schema/obd2-pid.schema.json",
  "version": 1,
  "type": "obd2-pid",
  "mode": "01",
  "entries": [
    { "id": "0C", "name": "Engine RPM", "length": 2, "unit": "rpm",
      "decoder": "rpm", "description": "Engine RPM ((256*A + B) / 4)" }
  ]
}
```

Optional entry fields: `scale`, `offset`, `min`, `max`. `decoder` names a
function registered in `ERD.Decoders`: `linear`, `percentage`,
`temperature`, `fueltrim`, `rpm`, `speed`, `maf`, `ascii`, `bitfield`,
`raw`, `signed`.

### Text catalogues (`obd2-dtc`, `uds-nrc`, …)

```json
{
  "$schema": "https://erdesigns.eu/schema/text-catalog.schema.json",
  "version": 1,
  "type": "uds-nrc",
  "entries": [
    { "code": "0x33", "text": "securityAccessDenied" }
  ]
}
```

### OEM overlays (`catalogs/oem/<vendor>/*.json`)

Loaded by `TOBDOEMCatalog` (`FileName`, `OEM`, `AutoLoad`, `Load`,
`OnLoaded`). Any subset of the top-level arrays is accepted:

```json
{
  "oem": "vag",
  "dids": [ { "id": "0xF190", "name": "Vehicle Identification" } ],
  "pids": [ { "mode": "0x22", "pid": "0xF1A0", "name": "Coding Index" } ],
  "dtcs": [ { "code": "P171F", "name": "Lambda Bank 1 Slow" } ],
  "spns": [ { "spn": 1234, "name": "Custom SPN" } ],
  "fmis": [ { "fmi": 31, "name": "Vendor-specific" } ],
  "pgns": [ { "pgn": "0xFE56", "name": "Custom PGN" } ]
}
```

### Coding-option catalogues (`oem-coding-catalog.schema.json`)

The package ships only the schema; option content is dealer / workshop
database material that hosts supply and load with
`TOBDCodingOptionCatalog`. Each option names its addressing inside the
coding buffer — `byte_bit`, `byte_field`, `byte_range`, `tlv_id`,
`config_word`, `asbuilt_section` or `menu_index` — and optional value
labels. Hosts look options up by vendor, module and name
(`TryFindOption`) and feed the addressing record to the matching per-OEM
coder unit.

```json
{
  "version": 1,
  "vendor": "vag",
  "module": "09",
  "options": [
    {
      "name": "Coming home",
      "addressing": { "kind": "byte_bit", "byte": 4, "bit": 0 },
      "values": [
        { "raw": 0, "label": "Off" },
        { "raw": 1, "label": "On" }
      ]
    }
  ]
}
```

### Flash-handshake overrides (`oem-flash-handshake-catalog.schema.json`)

Per-platform overrides on bootloader handshakes. Hosts populate them from
their own ground-truth sources (ISTA / ODX / vendor service docs), look a
platform up with `TryGetPlatform` and apply it with
`TOBDFlashOEMCatalog.ApplyTo(Handshake, Platform)`. Defaults are built
into source; the catalogue is only consulted for explicit overrides.

### Image applicability (`flash-image-applicability.schema.json`)

A sidecar shipped with a firmware image that declares which ECUs the
image may be flashed to. `TOBDFlashImageApplicability.Load` reads it,
`MatchesImage` checks the image SHA-256 and `Verify` reads each declared
DID through a `TOBDDataIdentifierIO` and evaluates the rule; wire both
into an `fpVerifyImage` check so the pipeline refuses any mismatch.

```json
{
  "version": 1,
  "image_sha256_hex": "<64 hex characters>",
  "vendor": "vag",
  "constraints": [
    { "did": "0xF190", "match": { "kind": "exact", "value": "WVWZZZ1KZ7W123456" } },
    { "did": "0xF191", "match": { "kind": "any_of", "values": ["1A2B3C", "1A2B3D"] } },
    { "did": "0xF195", "match": { "kind": "hex_prefix", "value": "1234" } }
  ]
}
```

Match kinds: `exact`, `any_of`, `regex`, `hex_prefix`.

### Shared bases (`"extends"`)

Generic data that many brands share — the generic OEM DID / routine /
live-data template and the generic DTC extended-data records — lives once
in `catalogs/_shared/`. A full OEM catalogue names its base in the header:

```json
{
  "$schema": "./_schema/oem-catalog-v2.json",
  "version": 2,
  "manufacturer_key": "BYD",
  "default_source": "byd-service",
  "extends": "_shared/oem-cars-and-trucks.json",
  "dids": [ { "did": "0x2101", "name": "BYD specific" } ]
}
```

`TOBDOEMJSONCatalog` loads the base first (with the base's own
`default_source` / `default_ecu_address`) and then the brand's entries, so
a brand entry with the same key replaces the inherited one. The path is
relative to the catalogue's folder (vehicle-class catalogues use
`../_shared/oem-<class>.json`); absolute paths, missing bases, cycles and
chains deeper than four levels are rejected. `CreateFromText` needs a
base folder when the text uses `extends`.

A sister brand can also extend its parent brand catalogue instead of a
`_shared/` base — `dacia.json` extends `renault.json`, `polestar.json`
extends `volvo.json`, `mini.json` extends `bmw.json`, and `bentley.json`
and `lamborghini.json` extend `vw.json` (which itself covers Volkswagen,
Audi, Škoda, SEAT and Cupra). The parent's chain is followed, so
the sister brand still gets the shared template; it only keeps the entries
that differ from its parent.

`tools/validate_catalogs.py` checks the chain, rejects brand entries that
merely repeat an inherited one, and fails when an entry is copied
identically into more than five unrelated catalogues beyond the
`SHARED_ENTRY_BUDGET` — move such data into a `_shared/` base instead.

## Adding an entry

1. Find the right catalogue under `catalogs/` (or create one of the right
   type).
2. Add the entry in the format its schema in `catalogs/_schema/` dictates.
3. Validate:

   ```bash
   python3 tools/validate_catalogs.py --require-coverage
   ```

   CI runs the same validation; a schema violation fails the build with
   the offending entry named.
4. If you added or removed OEM, DTC, universal or range-profile catalogue
   entries, regenerate `catalogs/INDEX.md` with
   `python3 tools/catalog_index.py --write` (and run
   `python3 tools/ev_support_matrix.py --write` after EV battery changes).
   CI fails when either generated document is out of date.

Catalogue files declare `$schema`, so JSON-Schema-aware editors (VS Code
and others) validate them while you type.

## Custom decoders

When a PID needs a calculation the built-in decoders don't cover,
register a decoder at run time:

```pascal
TOBDDecoderRegistry.Default.Register('my-special',
  function(const ARaw: TBytes;
    const ADescriptor: TOBDPIDDescriptor): TOBDValue
  begin
    Result := Default(TOBDValue);
    Result.Kind := vkFloat;
    Result.AsFloat := ARaw[0] * 0.5 + 12;
  end);
```

Then point the PID descriptor at it:

```json
{ "id": "42", "name": "...", "decoder": "my-special" }
```

## Versioning

Every strict catalogue carries `"version": 1`; the loader rejects any
other value, so a breaking format change ships as a new schema version
with a loader update. Other catalogue families carry their own
`version` or `schema_version` field, described in their schema under
`catalogs/_schema/`.
